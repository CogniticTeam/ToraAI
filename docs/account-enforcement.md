# 自动风控与申诉

公示规则来自根目录《Agent工具AI模型使用准则.md》，规则版本为 `2026-10-11.1`，公示路径 `/policies/agent-model-usage/`。原稿有独立备份，现行文件已按用户确认改为可执行版本。

## 自动处理范围

`/tochat/v1/chat/completions` 经登录鉴权后进入每账号的 `AccountEvents` Durable Object（命名 `fair-use:<userId>`）。计数只使用哈希后的请求和消息标识，不读取完整提示词或模型输出；不按政治观点、关键字、模型拒答或个人特征判定。

- 正常：600 个请求或 60 条新消息 / 60 秒。
- 限流及观察：120 个请求或 6 条新消息 / 60 秒。
- 工具续步按同一消息去重；少量重复请求只得到 HTTP 限流，不产生违规记录。
- 形成违规需要至少 20 个不同请求标识，同账号事件间隔至少 10 分钟。
- 一级限流 24 小时；90 天内累计三次独立一级事件升二级，最近 180 天二级事件按 7、15、30 天临时封禁。
- 临时限制到期后按服务器时间自动恢复；30 天观察期内再触发独立事件，会进入三级复核并保护性临时封禁 7 天，永不自动永久封禁。

永久处理需管理员核对三级案件、账号 ID 及复核依据。内容、版权和授权边界争议没有自动关键词封号路径，需要另行取得证据和人工处理。自有部署及个人模型直连流量不可由托管服务观察，不宣称全部覆盖。

## 状态及一致性

自动限制由 `enforcement_cases` 计算，与原有 `users.banned` 人工封禁分开。自动到期或撤销不能解除独立人工封禁。事件、申诉和复核保留审计，审批旧人工处罚的申诉不能撤销后来添加的新人工处罚。

DO 串行计数；事件写入失败会保留待写入意图并按同一 signal ID 重试，防止重复计分。异常时返回 503，不放行无法检查的模型调用。新计数在部署后开始，不扫描历史对话；限流发生在供应商调用和 Credits 预留前。

不清空订阅、Credits、重置卡、对话或文件，不把网络错误、配额不足、共享 IP 和设备变更直接计作违规。管理员复核及申诉只能改变对应记录；其他仍有效的限制继续生效。

## 管理和用户入口

- 管理端「风控与申诉」查询案件及处理申诉；现有账户列表同时显示自动限制。
- `GET /admin/enforcement`，`POST /admin/enforcement/cases/:id/review`，`POST /admin/enforcement/appeals/:id/review` 需要管理密钥。
- `GET /account/enforcement`、`POST /account/enforcement/ack`、`POST /account/enforcement/appeals` 需要账户身份，始终按 user ID 隔离，封禁期间仍可使用。
- 客户端提供原因、时间、规则、申诉和复核结果；桌面通过实时事件及轮询恢复状态，网页版轮询。原有客户端依然受服务端封禁约束，完整申诉面板需更新客户端。

迁移 `0012_enforcement.sql` 仅新增元数据、申诉、审计及人工处罚版本表。`ABUSE_ENFORCEMENT_ENABLED=0` 可关闭新的自动检测（不撤销已生效的案件）；解除误判应通过对应事件的复核，而非删除台账。先部署官网准则，再部署启用规则的 Worker。

已设置每周一 10:00（GMT+8）本对话维护任务。文字及已实现功能描述可以适当修订；处罚、监测、收费、权益及申诉的实质变更先提出建议，不自动修改真实用户记录或永久封号。
