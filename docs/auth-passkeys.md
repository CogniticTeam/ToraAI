# 登录与通行密钥

桌面登录采用居中分步流程：登录入口、选择其他方式、邮箱或已有用户名、密码、人机验证、邮箱验证码。新注册账号使用邮箱和密码；已有用户名仍可登录。Google、Apple、Microsoft 与电话号码登录未接入，不展示无效入口。界面和通行密钥验证页覆盖现有语言包与深浅色主题。密码最少 8 位，与现有 Tora 服务一致。

邮箱验证码通过 `/auth/email-code` 发放，用途为 `signup`、`login`、`reset`。发送必须通过服务端 Turnstile，并受到邮箱冷却、发送上限和 IP 限流保护；验证码以 SHA-256 存储，10 分钟有效、最多尝试 5 次，一次消费且绑定用途和账号。密码重置先兑换 5 分钟的单用途令牌，完成后撤销该账号已有会话。

通行密钥使用 `@simplewebauthn/server` 验证 WebAuthn。RP 为 `ohfun.online`，验证页固定为 `https://tora.ohfun.online/auth/passkeys`；桌面 localhost 页面不伪装成官网 origin。客户端先建立 5 分钟的单次请求，再打开系统浏览器，用户比对六位确认码并确认验证。请求标识放在 URL fragment，页面读取后立即清除，不发送给网页请求日志或 Referer。领取秘密只留在客户端内存；服务端只保存哈希，验证页面仅返回成功标记，不接收登录令牌。

挑战绑定请求、用途、账号、RP 和 origin，2 分钟有效且一次消费。签名、用户验证与计数器由库验证。服务端不保存私钥。新密钥要求可发现凭据与用户验证，最多 10 个。添加和删除密钥需要已登录的会话及再次验证当前密码。取消请求会阻止尚未完成的验证。通行密钥登录不直接免除免费体验的人机验证门槛。

管理入口：设置 → 账号 → 通行密钥。数据库扩展为 `0013_auth_passkeys.sql`，只添加新表，不改动既有账号、订阅、额度或聊天记录。旧登录/注册接口保留兼容。

验证范围：独立 P-256 软件认证器与 SQLite 测试覆盖注册、真实签名登录、错误签名、域名/账号/UV 失败、重放、一次领取、取消、过期与账号隔离；前端回归覆盖登录入口、注册/验证码步骤、语言包与迟到响应。实际 Touch ID、Windows Hello 或手机确认须由用户在系统提示中完成，软件签名测试不能替代真实设备验证。
