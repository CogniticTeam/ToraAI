# Tora 订阅与工作额度

普通 ToChat 聊天不扣工作额度，也不按消息条数限额。ToChat 工作模式和 ToCode 的内置模型共用当前账号的工作额度。自定义模型使用用户自己的提供商账户，不扣此额度。

## 计量

后台用整数微 Credit 对账。缓存输入属于总输入的一部分，先从普通输入中扣除再按缓存费率计算；输出已包含推理 Token，不再重复计费。每笔用量保存模型、功能、时间戳和原始 Token 明细。超过 272000 输入 Token 的 GPT Sol 请求使用长上下文费率。

费率和各窗口容量在 `packages/auth-worker/src/subscription-plans.js` 配置；Worker 的 `AGENT_CREDIT_RATES` 可覆盖费率。它们是 Tora 的服务计量规则，不能当作 OpenAI 官方计费或枢流云当前报价。初始费率采用保守成本缓冲，后续应依据实际上游账单、缓存命中率及成本调整。GPT 当前仍为 default 分组，不承诺 codex 0.07。

请求开始时按保守上下文大小和允许输出预留额度，SQL 触发器原子检查所有启用窗口，避免并发透支。流式生成时更新预估消耗，结束后按上游真实输入、缓存输入、输出校准并释放未用预留。未返回可靠用量的中断请求保留保守用量并标为 unknown，供对账处理。UI 每两秒刷新，只展示剩余百分比与下一次窗口释放时间。

所有窗口按当前时间往前滑动，没有每日零点或周一清零。任何一个生效窗口耗尽时停止接收新的内置模型工作请求；单个请求的输出上限也受剩余额度约束。窗口释放额度且订阅仍有效后可以继续使用。

## 爱发电

已核对六个商品 ID 与公开价格。购买入口打开对应爱发电商品页，付款后在“设置 → 账号 → 兑换权益”输入订单号。通过应用支付意图绑定过账号的订单不能兑换给其他账号；未绑定的商品订单只允许一次兑换。客户端的付款声明、昵称和留言不能直接发放权益。服务端使用 [爱发电开放 API](https://guide.afdian.com/creator/developer) 签名查单，并校验成功状态、商品 ID、付款金额与订单归属；订单号和支付意图均唯一，重复回调不会重复发放。

爱发电未在开发者文档中提供 Webhook 签名字段，因此通知必须通过带私密 key 的 URL，并再次从开放 API 查询真实订单。已绑定支付意图的订单兼容自动同步。普通商品页购买使用订单号兑换；即使回调未到达，也可直接查单兑换权益。

Worker Secrets：`AFD_USER_ID`、`AFD_TOKEN`、`AFD_WEBHOOK_KEY`。禁止放进客户端或公开仓库。Webhook 地址格式为 `https://tora.ohfun.online/billing/afdian/webhook?key=<私密值>`，需在爱发电开发者后台配置。API 授权失败不会泄露上游返回的调试签名或 Token。
