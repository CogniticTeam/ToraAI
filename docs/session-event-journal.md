# 会话恢复日志

桌面端 ASAPI 会话仍以 `~/.tora/asapi/sessions/<id>.json` 保存兼容快照。新回复同时写入同目录的 `<id>.events.jsonl`，每行是一个已提交事件；写入后同步落盘。旧会话没有日志时继续读取原 JSON。

桌面工作会话在调用工具前同步保存调用记录，拿到结果后追加 `internal-append`。上下文压缩时写入新的 `internal-snapshot`。回复进度用 `reply-progress` 保存，回复结束用 `reply-finished` 同时保存最终展示和模型上下文。加载时只重放 JSON 中 `__journal_offset` 之后的完整事件行。保存 JSON 前先合入新事件并更新游标。

进程在写入一行中途退出时，读取忽略不完整的末行，下次追加先截去该末行。完整行若损坏，保存时先将日志隔离为 `.corrupt-*`，保留 JSON 快照并开启新日志。没有 `reply-finished` 的回复由历史接口标为 `interrupted`，等待确认的工具卡片也会失效。删除会话时一并删除日志；从会话分支时，先读取已重建的历史，再创建独立会话。

继续中断的工作会话时，已落盘的工具结果原样复用。只有调用记录的工具会被标为执行结果未知，以配齐模型协议并提示 Agent 检查工作区和外部状态。工具执行须经一次新的模型调用及权限检查。

工作会话的「继续」按钮适用于中断和达到轮数上限的最新回复。续跑沿用原始请求和当前会话配置，并产生一条关联到原回复的新回复。上下文压缩会保留原请求。

Bash、Git 和 MCP 的长文本输出经过现有脱敏规则后，模型上下文和会话日志保存首尾预览。原始捕获内容最多每条 1 MiB，每会话保留 32 MiB，保存为本机私有文件。Agent 用 `ToolOutput` 按 ID 分段读取当前会话的内容。分支会复制保留消息引用的输出文件，删除会话会清理相应副本。进程输出上限和 Git 的显式 `max_chars` 仍会限制可捕获内容。

回复的 `metadata.harness` 保存运行结果、首个请求的工具数量和估算 token、模型实际回报用量及运行耗时。流式正文每 1.5 秒保存一次进度，进程突然退出可能丢失最后一段文字。

计时中的 `modelWaitMs` 是模型请求等待时间，含流式输出和辅助请求。 `toolBatchMs` 是工具批次等待时间，含权限、钩子和该批次的持久化。权限判断按 JSON 快照版本读取当前设置，会话事件增长时无需重放历史。

同一轮内已读取的文件发生变化后，`Write` 和 `Edit` 会要求重新读取。文本修改通过临时文件提交并保留原有权限位。工作区检查点在工具通过权限和参数检查后建立。

用 `npm test` 验证日志重放、持久 shell 中断、分支、有副作用的工具调用恢复和完成校验。只跑桌面 Harness 回归可执行 `node --test packages/core/test/desktop-harness.test.mjs`。
