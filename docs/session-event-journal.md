# 会话恢复日志

桌面端 ASAPI 会话仍以 `~/.tora/asapi/sessions/<id>.json` 保存兼容快照。新回复同时写入同目录的 `<id>.events.jsonl`，每行是一个已提交事件；写入后同步落盘。旧会话没有日志时继续读取原 JSON。

事件包括 `run-started`、`reply-progress`、`internal-snapshot` 和 `reply-finished`。运行开始时保存用户消息及模型上下文；工具结果、上下文压缩和正常收尾时更新上下文；回复进度及最终状态用于重建展示消息。加载会话时只重放 JSON 中 `__journal_offset` 之后的完整事件行。保存 JSON 前先合入尚未保存的事件，再记录新游标，因此重命名、团队状态更新和分支编辑不会被旧事件覆盖。该游标不出现在 SessionView API 中。

进程在写入一行中途退出时，读取忽略不完整的末行，下次追加先截去该末行。完整行若损坏，保存时先将日志隔离为 `.corrupt-*`，保留 JSON 快照并开启新日志。没有 `reply-finished` 的回复由历史接口标为 `interrupted`，等待确认的工具卡片也会失效。删除会话时一并删除日志；从会话分支时，先读取已重建的历史，再创建独立会话。

日志保留模型上下文和工具输出，按私有文件权限创建。它补足了进程退出后的恢复边界；流式正文仍按现有 1.5 秒节奏保存进度，突然退出可能丢失最后一段尚未落盘的文字。日志目前随会话保留，后续若出现大体积长期会话，应通过带校验的快照代际轮换控制体积。

验证入口：`npm test` 覆盖日志重放、截断尾行、分支、拒绝状态及中断恢复；`npm run test:ui:critical` 覆盖聊天回复呈现和输入区交互。
